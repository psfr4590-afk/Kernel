# ADR-019: Cryptographic Hashes for Audit Integrity

Status: ACCEPTED
Date: 2026-09-22
Decision owner: Project architecture

## Context

Kernel audit evidence must provide detectable integrity failures without treating a hash as proof of truth.

## Decision

Kernel will use a **cryptographic hash** to detect modification of protected audit/evidence representations.

The hash covers a canonical representation of the protected record. The algorithm and encoding metadata must be explicit so that verification is deterministic.

A valid hash proves consistency with the hashed representation; it does not prove that the underlying event was truthful, authorized, or generated by a trusted external system.

Hash storage and verification must be separated from ordinary mutable application fields.

## Architectural consequences

Audit tampering becomes detectable when the protected representation or its hash relationship is altered.

A cryptographic hash is not itself a signature, key-management system, or external trust mechanism.

## Verification

Tests must cover deterministic hashing, altered payload detection, altered metadata detection, hash mismatch handling, algorithm/version metadata, and verification failure behavior.
